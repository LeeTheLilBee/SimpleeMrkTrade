# OBRES001–005 — fail-closed source recovery and safe revalidation

Exact parent: `97dd13745962b5917b520a79827a80f7651a7dc7` (accepted OBATTN001–005). Canonical non-actuating authority: `OB_RECOVERY_REVIEW_V1`.

OBRES does **not** create a provider fallback connector, second risk/position/capital ledger, automated retry loop, live kill-switch mechanism or permission to restart. It takes fully reverified OBATTN → OBSOUL → OBREC/OBSAFE → strategy/portfolio/position/time/mode source lineage. Owner/source-asserted per-account, per-component observations must carry explicit source ref/revision, SHA-256 integrity fingerprint, observed/received/expires instants, one of OUTAGE, STALE, CONFLICT, UNKNOWN or RESTORED_ASSERTED. Each observation is immutable and independently reverified. The review has an explicit as-of, chronological replay denial, source expiry and no cross-account or cross-component pooling.

Restoration claims cannot be made by merely refreshing the wall clock or replaying a prior source hash/revision. Two distinct chronological underlying source observations are required for a component to mark *its own* restoration as doubly asserted. An unknown/missing/expired source or any component left unreconciled keeps recovery blocked for new canonically verified use. Even when **all** requested components report two distinct restoration claims, the only resulting state is `FRESH_CANONICAL_REVALIDATION_REQUIRED`. It is **not** actual source reconciliation, authenticated provider status, settled money, released reserve, reinstated Tower permission or a live trade green light. A pre-existing canonical safety BLOCK remains `CANONICAL_BLOCK_RETAINED` regardless of asserted source restoration, and missing OBSAFE/owner-fit evidence still requires a fresh independent upstream review.

Source-specific next checks include new OBTIME/freshness, OBPOS fill/mark lineage, bank/broker provider-authenticated settlement and reconciliation, Tower owner/step-up, hosted revision and separate Teller acquisition-readiness truth. Teller owns deployment and BuyBox only reads Tower-authorized Teller readiness. Provider failure does not change architecture or justify raiding protected reserves.

Hard disabled effects: automatic provider failover, restarts, command replay, live notifications, automatic kill-switch clearing, policy/mode unlock, broker submission, capital transfer, real-money claims or direct OB–BuyBox. This is the first source-contract family; actual provider adapters, independent account authentication, manual-outage procedures, hosted exercise and separately approved owner recovery are still gated. Focused/full repository CI required before acceptance. Next externally gated OBML remains owner-only brokerage placement without an OB broker order API.
