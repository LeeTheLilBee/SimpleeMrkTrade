# OBSIM076–080 — current-token authentication for read-only hosted owner rehearsal

**Context:** The default-OFF Tower hosted synthetic Proof/Demo owner rehearsal already rotates its anti-CSRF token on explicit `/new.json` and makes mutations recheck that token under the same lock. A GET `/status.json` or `/sample.json` previously checked the token in `before_request` but could cross a concurrent `/new` between that check and the actual view. The old token could then observe the newly rotated workspace/status. Even though this is fictional Proof/Demo, rotation must revoke both mutation and read capability.

**Correction:** Both GET handlers independently bind current workspace and supplied header token inside the same process-local RLock used by `/new`. The old request returns 409 rather than presenting the successor workspace. Every regular unauthorized owner/session/step-up/OB-launch and Host gate remains in the existing Tower guard before this view. The checked-in synthetic sample remains fictional and never an external provider feed.

**Deterministic acceptance:** The new HTTP test injects an intervening same-Tower-session second-tab `/new` *after* first-tab `before_request` approval and *before* status or sample view; it verifies old GET 409 and new token 200. Tests also assert missing workspace, invalid token, disabled default, and real broker/capital/mode flags never promote. No new hosting, provider, token store, archive, deployment setting, permission or paid resource. Owner-site/revision selection, actual owner browser walkthrough, and ephemeral-data acceptance remain separate OPEN release gates.

The only implementation change is in `tower/ob_hosted_owner_rehearsal.py`; the feature remains disabled unless a specifically reviewed deployment sets both exact server-side feature flag and HTTPS origin. No modification to canonical Tower launch, protected route registry, OBTIME/CAPSIM, trading mode controls, Trust/ATM protected reserves or BuyBox/Teller boundary.
