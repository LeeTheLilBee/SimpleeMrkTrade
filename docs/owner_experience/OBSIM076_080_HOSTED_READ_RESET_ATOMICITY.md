# OBSIM076–080 — hosted owner rehearsal reset/read atomicity

A confirmed bug existed between the `before_request` workspace-token check and the subsequent `/status.json` or `/sample.json` view. A concurrently authorized `/new` reset could rotate the workspace/token after the gate checked the former token, but before the read-side view retrieved the replacement workspace. The old token's already-passed request could then receive a 200 response for the new rehearsal. This is a TOCTOU authorization problem; ordinary sequential old-token revocation tests do not prove the race is closed.

The fix rechecks exact current owner-session scope, workspace object identity and constant-time current anti-CSRF token while holding the same `RLock` used for reset, through completion of the read. A rotated token receives only `409 REHEARSAL_SESSION_ROTATED_REENTER_TOWER` with safety-false fields; it never receives replacement source data, report state or a new token. There is no new auth mode or route. Rechecking `scope()` also fails when Tower authorization is withdrawn between the first gate and the view.

`tests/test_obsim076_080_hosted_reset_read_atomicity.py` inserts a test-only callback between the actual Flask gate and handler, swaps the private workspace while holding its production lock, and tests both read APIs. It also simulates revoked Tower operational receipt between the gate and read, then tests legitimate reset and explicit synthetic-only input after new-token issuance. The browser remains same-origin. Report store remains volatile; Manual Live/Hybrid/Auto/broker/capital gates remain false.

This is a source-only correctness/security PR against the dedicated Tower branch. The reviewed hosted feature is disabled unless its separate exact origin and explicit opt-in are configured. No environment/deploy/Render changes, paid services or trading authority. CI intentionally names a focused, relevant Tower/OB suite; the historic unrelated full Tower suite is not claimed clean.
