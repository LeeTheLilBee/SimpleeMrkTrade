# Tower → Grounds current authority reconciliation (source-only)

Date: September 28, 2026. Grounds source parent PR #51 is at GRD162 and remains draft. This module is authored on the **hosted Tower development branch**, not the Grounds product branch.

`tower.grounds_current_provider_admission.inspect_current_ground_grants` introduces a separate server-only step after a real Tower auth provider and independently current Grounds residency/staff provider exist. It re-queries Tower using a server-selected session reference, derives the subject/role exclusively from Tower's fresh result, then queries current Grounds membership for exactly that derived subject and role. An exact property/unit-pair relation is preserved rather than mixing an allowed unit from one property with another property. It rejects revoked/expired/mismatched subject, role, lease, duplicate property/unit pair, missing resident active lease, and job-scoped staff with no current job assignment. Results expire within sixty seconds and are **candidates**, not grants; a later request must query again. Tests cover revocation between requests and private provider error non-disclosure.

**This is not the certified real provider implementation**. Neither provided function is available from this branch, and mere fields such as `verification_state=VERIFIED` cannot establish an issuer's authenticity. A trusted server composition and independently authenticated, current, non-forgeable providers must be provided and evaluated by the Tower/security operator. This module has no HTTP route, issuer, signing key, replay ledger, receiver factory, staff-directory factory, operational-release factory, tenant/staff session, identity provisioning or checkout. Specifically, do **not** create `tower.grounds_runtime_receiver.create_certified_grounds_receiver()` by wrapping this review alone. Grounds' exact production factory still fails closed.

The independent `tower.grounds_operational_release.create_certified_grounds_operational_release_guard()` remains unimplemented until current, nonrevoked owner approval and separately verified provider/recovery/privacy/legal/on-call/delivery readiness exist. Tenant storage, Teller, Vault, notifications and hosted owner acceptance are also distinct. No paid service, real tenant/account, money flow, notice or app launch is activated.
