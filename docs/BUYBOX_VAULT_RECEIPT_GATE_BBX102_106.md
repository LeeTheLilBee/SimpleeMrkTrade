# BBX102–106 — Authenticated Vault archival receipt gate\n\nBuyBox already prepared metadata-only buybox.vault.evidence.v1 drafts and could correlate an untrusted response. BBX102–106 closes the BuyBox-side acceptance gap without pretending the Tower/Vault corridor is live.\n\nA canonical ARCHIVED response can be recorded only when a separately injected trusted Tower/Vault response verifier authenticates the transport. BuyBox then rechecks the response against the exact request ID, evidence ID, frozen decision snapshot, source document, and SHA-256 digest. Missing, pending, mismatched, incomplete, or browser-shaped responses fail closed.\n\nThe stored local proof is minimized to opaque receipt/version references, exact source digest and evidence linkage. It never stores raw document bytes, credentials, paths, download tokens, or payment data, and never authorizes purchase or money movement.\n\nThis implements the receiving side only. The actual authenticated Tower→Vault→Cloud corridor, malware scan, canonical Vault transaction, retention enforcement, provider durability and real receipt issuance remain owned by their respective systems and must be independently proven before real documents are treated as archived.\n
