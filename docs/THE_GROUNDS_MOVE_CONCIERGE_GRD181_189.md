# Grounds GRD181–189 — Move-In/Move-Out Concierge, source only

Resident planning checklists are now real, lease-scoped source records, not a fictional static mockup. Their purpose is to make move planning easier without granting legal, financial, physical or document authority to a resident's self-reported checkbox.

- `grounds/move_concierge.py` uses current `GroundsOperations._resident_lease` inside a write transaction for each update. A resident sees only checklist items for their current exact lease/property/unit and their own subject ref. Another member of the same unit does not inherit their checklist. An ended lease or revoked Tower grant cannot read or post a new self-report.
- Source-defined move-in and move-out tasks contain only non-sensitive, descriptive planning milestones; they do not ask for forwarding addresses, banking records, account passwords or actual photographs. Each task has an append-only `move_task_events` record with expected revision, current scope, server timestamp, strictly local planned/self-reported-done status and browser UUIDv4/server-derived idempotency reference. Exact retry rechecks CURRENT lease/subject before returning the same result; changed replay or stale revision conflicts before persistence.
- The resident browser shows both phases, progress and a real action to mark a task planned/personally reviewed or reopen planning. Every card labels the mark as a personal record, not a staff-verified inspection, actual key receipt, lease-end amendment, deposit decision or notice delivery. There is no uploaded document or legal approval button.
- `GET /grounds/api/move-desk?property_ref=` is owner/property-manager ONLY and returns aggregate counts of active leases with recorded end dates within 60 days, units recorded make-ready, unfinished turnover workflows and open turnover inspections. It contains no resident subject/name or protected personal data, does not decide renewals, notices, deposit disposition or actual key custody. Other roles and properties are denied. This reuses the existing independently controlled owner/staff/turnover domains.
- The append-only source table and index are included in FRESH fictional SQLite and private PostgreSQL baseline plus schema preflight/fixture integrity. No production migration, real tenant data, hosted database or new paid resource exists. If a real older private DB ever exists, its versioned migration needs separately approved backup/review/restore and must not be silently applied by the app.

`grounds/test_grounds_move_concierge.py`, `test_grounds_web.py` and actual disposable `test_grounds_postgres.py` cover self-report, exact retry, revision mismatch, same-unit nonmember, ended lease, manager aggregate redaction, unexpected fields, no false money/key/legal approvals and genuine SQL persistence. Exact source and PostgreSQL checks must pass on child and parent heads before source acceptance.

Future genuine move-in/out operations still require actual Tower identity/current lease and separate operating-release certification; Teller ledger/checkout/deposit receipt and compliant decisions; Vault condition photos, signed inspections and protected forwarding records; real scheduling/provider delivery; applicable property law, accessibility/privacy review and explicit owner approval. A complete checklist is not a legally completed move.
