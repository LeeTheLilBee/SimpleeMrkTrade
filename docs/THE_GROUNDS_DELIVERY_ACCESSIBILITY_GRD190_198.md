# Grounds GRD190–198 — communication evidence/exception desk and UX guardrails

## A meaningful delivery state is not the same as a local intent

`grounds/delivery_desk.py` adds authenticated owner/property-manager/maintenance-supervisor-only, exact-property `GET /grounds/api/delivery-desk`. It reads the already append-only `event_outbox` and independently verified `event_delivery_receipts`; no new proof verifier or delivery sender is fabricated.

The protected response gives a total of locally recorded event intents, count lacking **historical independently verified delivered notification receipts**, and a bounded, oldest? **most-recent-first 50-event** index with exact source revision, latest verified historical notification state and (only for urgent source intents) the latest historical human escalation acknowledgment state. The visible subset reports items needing provider review; this is NOT an exhaustive count when truncated. The app never relabels `event_outbox.status=pending` as provider-delivered, and a later verified failure remains visible. No resident identity, message body, recipient address, provider secret or legal notice is exposed. Property-bound current Tower grant is mandatory on every read.

The real staff app shows the historical status, unconfirmed count and visible exception queue, explicitly states that **current provider connectivity, recipient resolution and external retry remain disconnected**, and does not render a fake Resend/Delivered/Dispatch button. **Follow-up GRD208–211:** a gateway \`accepted\` receipt remains an unconfirmed delivery requiring provider review, and urgent \`queued\` remains unacknowledged until a verified \`human_acknowledged\` receipt; only historical \`delivered\` can resolve the notification-side visible exception, without implying current connectivity or legal service. Existing receiver-side append-only receipt replay and verification remains unchanged. Actual notification retry/dead-letter policy, provider message/recipient verification and on-call roster require separately certified upstream integration, reviewed retention and owner acceptance.

## Accessibility and privacy source checks

`grounds/test_grounds_accessibility_source.py` checks labeled source landmarks/controls, skip-to-content, current role panel headings, in-app status announcements, reduced-motion support, focus-visible treatment, nonpersistent larger-text toggle, base foreground/background and muted contrast, plain-text DOM rendering, absence of local/session storage, context invalidation and CSRF/idempotency. It is a deterministic code regression, **not** a replacement for hosted keyboard, screen reader, low-bandwidth, high zoom, mobile and actual human accessibility acceptance. Real-world legal/privacy approval still belongs to qualified professionals and the owner.

The application still uses separate Tower authorization and independent owner-operational release gates, actual approved private PostgreSQL, Teller-only money and Vault-only protected originals. Both exact child and merged parent source-only + disposable PostgreSQL suites must pass. No paid hosting, tenant data, external SMS/email, urgent emergency call, legal service, real customer account or public Grounds launch occurs from this change. Keep PR #51 draft until external certifications and explicit owner-hosted walkthrough are complete.
